# Battery Tray

[English](README.md) | **Русский**

**Универсальный** индикатор заряда беспроводных мышей, геймпадов и
Bluetooth-устройств в системном трее Windows (раньше — *Mouse Tray Charge*).
Одно приложение, много производителей — добавление нового вендора или модели —
это один небольшой файл, без изменений в UI и коде опроса.

![Скриншот](images/screenshot.png)

## Поддерживаемые модели

- **ATK / VXE / VGN:** ATK F1 Ultimate, ATK A9 Ultimate, ATK Zero, VXE MAD R,
  VXE MAD R Major Plus, VXE R1 Pro Max, VXE R1 SE+, VGN F1 Pro, VGN F2 Pro Max
- **Zaopin:** Z2 Mini
- **Scyrox:** V8
- **Dareu:** A950 Air, A950 Wing
- **G-Wolves:** Lycan
- **MCHOSE:** L7 Pro
- **Ninjutso:** Sora V2
- **Razer:** Viper V2 Pro, Viper V3 Pro, DeathAdder V3 Pro, DeathAdder V4 Pro,
  Basilisk V3 Pro, Basilisk V3 Pro 35K, Basilisk Ultimate, Cobra Pro, Naga Pro,
  Naga V2 Pro, Lancehead Wireless, Pro Click V2
- **Lamzu:** Maya X, Inca
- **Attack Shark:** X3
- **A4Tech Bloody:** SG5 Pro (донгл 8K)
- **Logitech:** любая мышь Lightspeed/Bolt/Unifying с фичей UnifiedBattery —
  через ресивер **или при прямом подключении по USB-кабелю / Bluetooth**
  (название модели определяется автоматически по HID++) — проверено на
  PRO X2 SUPERSTRIKE (ресивер и провод)
- **Геймпады Sony:** DualShock 4 (v1, v2, USB-адаптер), DualSense, DualSense
  Edge — по USB и Bluetooth. На железе ещё не проверено; геймпад, скрытый
  DS4Windows/HidHide в эксклюзивном режиме, не виден.
- **Bluetooth:** любое сопряжённое устройство, заряд которого Windows сама
  показывает в «Параметры → Bluetooth и устройства», — BLE-мыши, клавиатуры
  и геймпады, классические гарнитуры. Windows сообщает только уровень, поэтому
  анимации зарядки нет. Устройство, которое уже читает другой драйвер (мышь
  Logitech по Bluetooth), остаётся за ним. К имени добавляются последние
  четыре цифры Bluetooth-адреса, например `WH-1000XM4 (E4F5)`, чтобы два
  одинаковых устройства не путались.

> Драйвер Razer портирован с реализации на `pyusb` на `hidapi` ради
> единообразия; смещение в отчёте / HID-коллекцию может потребоваться уточнить
> на железе (см. примечание в [`drivers/razer.py`](battery_tray/drivers/razer.py)).
> На реальном железе проверена только **Viper V2 Pro** — остальной список взят
> из базы устройств [OpenRazer](https://github.com/openrazer/openrazer). Это
> модели, у которых запрос батареи использует transaction id `0x1F` (именно он
> зашит в драйвере), поэтому код менять не нужно; более старые семейства Razer
> с `0x3F` / `0xFF` пока не поддержаны. Если непроверенная модель показывает
> неверно — уточните смещение ответа / `usage_page` на железе.

## Установка

Установщика нет: программа — это папка с `battery_tray.exe` и каталогом
`_internal\` (Python и библиотеки). Чтобы установить или обновить:

1. Закройте запущенную копию (значок в трее → **Exit**).
2. Скачайте zip из [Releases](https://github.com/Resmus1/battery_tray/releases) и
   распакуйте.
3. Скопируйте `battery_tray.exe` **и** `_internal\` в
   `%LOCALAPPDATA%\Programs\battery_tray`
   (`C:\Users\<имя>\AppData\Local\Programs\battery_tray`) с заменой файлов.
4. Запустите `battery_tray.exe`. При самом первом запуске программа сама
   добавит себя в автозагрузку.

**Обновляетесь с Mouse Tray (0.4 и старше)?** Закройте её и установите новую
версию, как описано выше, в новую папку `battery_tray`. При первом запуске
программа скопирует старые настройки, таймеры и историю разряда из
`HKCU\SOFTWARE\Mouse_Tray` и перенесёт запись **Запуск с Windows** на новый
exe (отключение в диспетчере задач тоже переносится). После этого удалите
`%LOCALAPPDATA%\Programs\mouse_tray`. Для Windows это новая программа, поэтому
её значок нужно один раз включить в «Других значках в системном трее»; старые
логи остаются в `%LOCALAPPDATA%\Mouse_Tray`.

Почему `%LOCALAPPDATA%\Programs`: это стандартное место Windows для программ
одного пользователя (туда же ставятся VS Code, Discord и другие).

- **Не нужны права администратора.** Файлы в `C:\Program Files` можно заменить
  только через запрос UAC, а здесь это обычные файлы пользователя.
- **Совпадает с автозапуском.** Автозагрузка прописывается только для текущего
  пользователя (`HKCU\...\Run`), так что папка «для одного пользователя» логична.
- **Не синхронизируется.** Рабочий стол и «Документы» часто синхронизируются с
  OneDrive, и туда улетели бы ~67 МБ библиотек; `AppData\Local` не
  синхронизируется никогда.
- **Локальный диск.** Программа стартует, даже если сетевой диск или сервер ещё
  недоступен.
- **Не мешает.** Папка скрытая, её не удалишь и не переместишь случайно.

Можно выбрать любую другую папку на локальном диске — главное, чтобы exe и
`_internal\` лежали вместе. После переноса переключите **Start with Windows** в
настройках и заново включите значок в «Других значках в системном трее»: Windows
привязывает и то и другое к пути exe. `AppData` скрытая: откройте папку, вставив
`%LOCALAPPDATA%\Programs\battery_tray` в адресную строку Проводника или в **Win+R**.

## Запуск из исходников

Проект управляется через [uv](https://docs.astral.sh/uv/) — быстрый менеджер
пакетов и проектов для Python: он сам создаёт виртуальное окружение и ставит
зависимости (никаких ручных `pip install` и `venv`). Поставить один раз:

```sh
# Windows (PowerShell)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
# или через winget / pipx
winget install astral-sh.uv
```

Затем из корня проекта:

```sh
uv sync                      # создаёт .venv и ставит зависимости из uv.lock
uv run python main.py        # или:  uv run python -m battery_tray
```

`uv run` перед запуском сам подтягивает зависимости, так что после свежего
клона достаточно одной команды `uv run python main.py`. Файл `uv.lock`
фиксирует точные версии для воспроизводимой установки.

## Сборка автономного .exe

Релизы собирает GitHub Actions ([`.github/workflows/release.yml`](.github/workflows/release.yml)):
достаточно отправить метку вида `v0.2.0`, и сборка пройдёт на чистой Windows по
`uv.lock`, а zip прикрепится к релизу с именем метки. Собрать локально:

```sh
uv run --extra build python tools/make_release.py
# -> dist/battery_tray/
```

Сборка — это **папка**, а не один файл: `battery_tray.exe` загружает Python и
библиотеки (`python314.dll` и остальное) из каталога `_internal\` рядом с собой.
Копируйте или переносите папку `dist\battery_tray\` целиком — один exe без неё
не запустится с ошибкой «не найден python314.dll». Однофайловая сборка не
используется намеренно: она распаковывалась бы во `%TEMP%` при каждом запуске,
стартовала бы медленнее и чаще вызывала ложные срабатывания антивирусов.

Каталог сборки занимает около 37 МБ. Драйверы собираются целиком
(`--collect-submodules`), поэтому новый драйвер попадает в сборку без правок
скрипта. Модули, до которых приложение не дотягивается — кодеки Pillow, `ssl`
с его libcrypto/libssl, `wx.html` и подобные, — исключены списком `EXCLUDES` в
[`tools/make_release.py`](tools/make_release.py); там же указано, что исключать
нельзя. При появлении новой зависимости список стоит пересмотреть.

## Несколько мышей

Определяются все подключённые поддерживаемые мыши, а в трее показывается одна из
них. По умолчанию это первая, которая действительно ответила: приёмник с
выключенной мышью пропускается, а не показывается как «нет мыши». Выбранная так
мышь остаётся активной, пока не отключится.

Если подключено две и более, в меню трея появляется список: пункт **Auto** — то
самое поведение по умолчанию, либо можно закрепить конкретную мышь. Закрепление
строгое: если закреплённая мышь отключена, в трее `-`, а её имя показывается в
подсказке — на другую мышь индикатор молча не переключится. Выбор сохраняется в
реестре и переживает перезапуск. Опрашивается только показываемая мышь, так что
остальные ничего не стоят.

Настройка **Устройств в трее** (1–4) показывает несколько устройств сразу,
каждое своим значком, — например, мышь и геймпад. В режиме **Auto** тогда
показываются все ответившие устройства, но не больше заданного числа, и значки
появляются и исчезают вместе с ними; список в меню превращается в галочки,
каждая закрепляет одно устройство за своим значком. У каждого значка полное
меню; **Сбросить таймер** относится к устройству того значка, по которому
кликнули.

Таймер «времени с последней полной зарядки», оценка оставшегося времени и
уведомления о разряде ведутся отдельно для каждого устройства, поэтому
переключение сохраняет счётчики каждого из них.

## Настройки

Кликните по значку в трее правой кнопкой и выберите **Settings…**, чтобы из
диалога изменить интервал опроса, шрифт, цвет шрифта, окраску по уровню заряда,
вид индикатора и отладочное логирование. Изменения применяются сразу и
сохраняются в реестре (`HKCU\SOFTWARE\Battery_Tray\Settings`), поэтому переживают
перезапуск; кнопка **Reset to defaults** возвращает значения по умолчанию.

В списке шрифтов по умолчанию только моноширинные (цифрам нужна фиксированная
ширина); флажок **Show all fonts** открывает выбор любого установленного шрифта.
Ползунок **Text size** масштабирует цифры от 50% до 100% подогнанного размера,
а флажок **Text outline** (включён по умолчанию) сохраняет их читаемость на
панели задач того же цвета. Шрифт, размер и контур сразу видны в трее, диалог
закрывать не нужно.

Если включить **Color by charge level** (включено по умолчанию), индикатор заряда окрашивается по уровню
заряда: выше 50% — цветом шрифта, а рядом с ним появляются ещё два выбора цвета
для нижних диапазонов — **≤ 50%** (по умолчанию жёлтый) и **≤ 20%** (по
умолчанию красный).

Если включить **Show battery icon**, вместо цифр рисуется батарейка, заполненная
на текущий процент, а точное число уходит в тултип (там же имя мыши и время с
последней полной зарядки). Состояния «нет мыши», сон и неизвестный уровень в
любом случае остаются текстовыми.

**Устройств в трее** — сколько устройств трей показывает одновременно (по
умолчанию 1, до 4); см. [Несколько мышей](#несколько-мышей).

Флажок **Уведомление о разряде** (включён по умолчанию) показывает уведомление
Windows, когда заряд опускается до первого порога и ещё раз до второго
(**Уведомлять при**, по умолчанию 20% и 10%). Ниже нижнего порога уведомление
повторяется каждые **Повтор ниже нижнего порога** минут (по умолчанию 15, 0 —
один раз). Зарядка сбрасывает счётчик. Кнопка **Тест** сразу показывает
уведомление — так можно проверить, что Windows его пропускает (Параметры →
Система → Уведомления, режим «Не беспокоить»).

**Язык** переключает интерфейс между английским и русским; **Авто** — по языку
Windows.

### Оставшееся время

В подсказке значка показывается оценка вида `осталось ≈ 6 ч 20 мин`. Она
измеряется, а не берётся из паспорта: каждый раз, когда процент падает, время с
предыдущего падения даёт текущую скорость разряда, а оценка — медиана последних
шести таких отрезков. Расход зависит от настроек мыши — частота опроса (1K или
8K), DPI, motion sync — и от того, сколько ей пользуются, поэтому:

- если два последних отрезка оба отличаются от прежних больше чем в 1,8 раза
  (например, опрос переключили с 1K на 8K), старые отбрасываются, и оценка
  подстраивается под новый расход через два процента;
- затянувшийся простой считается ещё одним отрезком, так что час без движения
  не перекашивает цифру;
- время без показаний (компьютер спит или выключен, мышь выключена, программа
  закрыта) никогда не считается разрядом.

Пока не замечено двух падений, в подсказке написано `оценка времени…`. История
хранится отдельно для каждой мыши в реестре
(`HKCU\SOFTWARE\Battery_Tray\Discharge`) и переживает перезапуск.

Флажок **Start with Windows** включается автоматически при самом первом запуске;
дальше программа его никогда не трогает. Он добавляет программу в автозагрузку текущего
пользователя (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение
`Battery_Tray`); права администратора не требуются. Флажок отражает фактическое
состояние Windows, включая переключатель на вкладке «Автозагрузка» Диспетчера
задач, и не сбрасывается кнопкой **Reset to defaults**. При переносе папки с
программой запись перенаправляется на новое расположение при следующем ручном
запуске.

Полный набор полей (включая те, которых нет в диалоге) — в
[`battery_tray/config.py`](battery_tray/config.py):

| Поле               | Значение                                                   |
| ------------------ | ---------------------------------------------------------- |
| `poll_rate`        | Секунды между чтениями, когда мышь активна и разряжается   |
| `fast_poll_rate`   | Секунды между чтениями при зарядке/сне/отсутствии мыши     |
| `foreground_color` | Цвет цифр индикатора (RGB), он же цвет верхнего диапазона  |
| `dynamic_color`    | Окраска процента по уровню заряда (вкл.)                   |
| `mid_color`        | Цвет диапазона ≤ 50% (жёлтый)                              |
| `low_color`        | Цвет диапазона ≤ 20% (красный)                             |
| `battery_icon`     | Рисовать заполненную батарейку вместо цифр процента        |
| `background_color` | Фон значка (RGBA, по умолчанию прозрачный)                 |
| `font`             | Файл шрифта цифр (`consola.ttf`)                           |
| `app_name`         | Ключ хранилища: подраздел реестра + папка логов            |
| `display_name`     | Имя для пользователя (тултип трея, уведомления, настройки) |
| `low_battery_notify` | Уведомления о разряде (вкл.)                     |
| `notify_level_high` / `notify_level_low` | Пороги уведомлений, % (20 / 10) |
| `notify_repeat_minutes` | Повтор ниже нижнего порога, мин (15, 0 — выкл.) |
| `language`         | `auto`, `en` или `ru`                                      |
| `debug`            | Подробное DEBUG-логирование (сырые HID-отчёты)            |

## О программе

Пункт **About…** в меню трея открывает окно с версией и коммитом сборки, ссылкой
на страницу проекта и таблицей всех устройств, поддерживаемых текущей сборкой:
модель, USB-идентификатор (`VID:PID`, а также проводной PID, если по кабелю
устройство определяется под собственным) и протокол. Таблица сортируется кликом
по заголовку любой колонки и строится из реестра драйверов, поэтому всегда
соответствует реально включённым драйверам: сборка с новым драйвером покажет
его модели без каких-либо правок здесь.

## Логирование

Логи пишутся в ротируемый файл `%LOCALAPPDATA%\Battery_Tray\app.log` (1 МБ × 3
бэкапа), плюс в консоль, если она есть — у собранного оконного `.exe` консоли
нет, поэтому смотреть нужно в файл. Кнопка **Open log** в диалоге настроек
открывает его. Подробный вывод DEBUG (сырые HID-отчёты)
включается флагом `debug` в конфиге или переменной окружения
`BATTERY_TRAY_DEBUG=1`. Настройка — в
[`battery_tray/logging_setup.py`](battery_tray/logging_setup.py).

## Как добавить новую мышь

**Тот же вендор, новая модель** — добавьте строку в список `models` драйвера:

```python
# drivers/chipset/nordic52.py
_model("VXE NewModel", 0x373B, 0x1234, 0x5678),
```

> Драйвер `nordic52` покрывает общий **чипсет Compx/Nordic 52840**, а не только
> ATK/VXE/VGN. Многие «ноунейм»-мыши на том же кремнии (ресивер определяется как
> «Compx») заводятся одной строкой `_model` с их VID/PID — без нового драйвера.
> Zaopin Z2 Mini, Scyrox V8, Dareu A950 Air и G-Wolves Lycan добавлены именно так; если процент
> читается в байте 6 ответа на отчёт 8 — это тот самый протокол. Более новый кремний Nordic 54L15
> (ATK Zero) использует другой 64-байтный протокол и живёт в `nordic54`.

**Новый вендор** — создайте `drivers/vendor/<vendor>.py` (или
`drivers/chipset/<chip>.py`, если силикон общий для нескольких брендов),
унаследуйте `HidDriver`, перечислите модели и реализуйте `read_status()`:

```python
from ...battery import BatteryStatus
from ..driver import MouseModel, register
from ..hid import HidDriver

@register
class AcmeDriver(HidDriver):
    vendor = "Acme"
    models = [MouseModel("Acme X1", 0xABCD, 0x0001, 0x0002, usage_page=0xFF00)]

    def read_status(self) -> BatteryStatus:
        res = self._transact([0x00, ...], read_length=32, feature=True)
        if res is None:
            return BatteryStatus.absent()
        return BatteryStatus(present=True, percent=res[5], charging=bool(res[6]))
```

Затем добавьте `"vendor.acme"` в `_DRIVER_MODULES` в файле
[`drivers/__init__.py`](battery_tray/drivers/__init__.py). Готово — детект, UI трея
и сборка подхватят драйвер автоматически.

> Большинство мышей укладываются в `HidDriver` (один запрос, фиксированные
> смещения). Многошаговые протоколы вроде Logitech HID++ наследуют
> `HidppDriver` — но возвращают тот же `BatteryStatus`, поэтому UI/реестр не
> меняются. То, что два совершенно разных транспорта подключаются к единому
> контракту `MouseDriver`, — и есть главная идея архитектуры.

## Как это работает

Любая мышь, независимо от производителя, сводится к одной нормализованной
структуре [`BatteryStatus`](battery_tray/battery.py) — `present / percent /
charging / full / asleep`. Единый конечный автомат в
[`ui/app.py`](battery_tray/ui/app.py) превращает её в значок трея (цифры, анимация
зарядки, уведомление о полном заряде, тултип «время с последней полной
зарядки»). Код вендора делает всего две вещи: **находит устройство** и
**разбирает его отчёт о батарее**.

```
hid.enumerate (кэш 0.5 с)  →  detect_all_drivers()  →  driver.read_status()
        bus.py                    driver.py                → BatteryStatus
                                                                 ↓
                                                _apply_status() → значок трея
```

### Шина

[`drivers/bus.py`](battery_tray/drivers/bus.py) перечисляет всю HID-шину один раз
и кэширует снимок на 0.5 с. Детект перебирает каждую модель каждого драйвера —
десятки пар VID/PID, — поэтому сопоставление идёт в памяти, а не отдельным
сканированием шины на каждую модель. TTL заметно меньше самого быстрого
интервала опроса, так что мышь, подключённая на ходу, обнаруживается в пределах
одного тика.

### Драйверы

Контракт [`MouseDriver`](battery_tray/drivers/driver.py) — это два метода,
`detect_all()` и `read_status()`, плюс стабильный `key` (класс драйвера +
VID/PID), опознающий мышь после переподключения. Классы регистрируются
декоратором `@register`; список модулей в
[`drivers/__init__.py`](battery_tray/drivers/__init__.py) одновременно задаёт
импорт и порядок опроса при детекте. Ни один из методов не вправе бросать
исключение при отсутствующем устройстве или сбое ввода-вывода: ответом там
служат пустой список и `BatteryStatus.absent()`.

Под этим контрактом лежат две транспортные базы:
[`HidDriver`](battery_tray/drivers/hid.py) для типичного случая «один запрос — один
ответ» (подклассу остаётся только `read_status()` поверх `_transact()`) и
[`HidppDriver`](battery_tray/drivers/hidpp.py) для многошагового HID++ 2.0
(обнаружение фич, маршрутизация по индексу устройства). Общего кода у них нет —
именно поэтому настоящая абстракция здесь `MouseDriver`, а не какая-либо из баз.

Третьему виду протокол не нужен вовсе:
[`system/bluetooth.py`](battery_tray/drivers/system/bluetooth.py) читает уровень,
который Windows хранит для каждого сопряжённого Bluetooth-устройства
(PnP-свойство `{104EA319-6EE2-4701-BD47-8DDBF425BBE5} 2`, через CfgMgr32 и
`ctypes`), и считает устройство подключённым, пока у его узла нет флага
`DN_DEVICE_DISCONNECTED`. Он опрашивается последним, так что устройство,
которое читает HID-драйвер, дважды не показывается.

### Опрос

Цикл опроса выполняется в фоновом потоке-демоне. Детект повторяется каждый тик —
он стоит одного кэшированного перечисления шины, — поэтому мышь, подключённая
позже, появляется сама, без перезапуска. Объекты драйверов переиспользуются
между проходами по `key`, поскольку кэшируют состояние конкретного устройства
(HID++-драйвер, например, узнаёт индекс устройства и индексы фич при первом
чтении). Интервал равен `poll_rate` (по умолчанию 60 с), пока мышь активна и
разряжается, и `fast_poll_rate` (1 с) в переходных состояниях — зарядка, сон,
отсутствие мыши, — где важна быстрая реакция. К виджетам рабочий поток обращается
только через `wx.CallAfter`, так что вся работа с UI остаётся в главном потоке.

### Какая мышь отображается

Обнаруживаются все подключённые устройства, читаются только показываемые — не
больше `tray_icons`. Без закрепления рабочий поток берёт первые, ответившие
`present`, и держится за них — поэтому подключённый приёмник выключенной мыши
не перекрывает работающую. Закрепление из меню трея строгое: если закреплённое
устройство отключено, в трее отображается `-`, а не молчаливое переключение на
другое. Выбор хранится в реестре, и рабочий поток его только *читает*, что
оставляет объекты драйверов однопоточными. Каждое показание получает свой
значок; ненужные значки скрываются, а не уничтожаются, а всё, что программа
помнит об устройстве (таймер, оценка, уведомления), привязано к устройству, а
не к значку.

### Отрисовка

[`_apply_status`](battery_tray/ui/app.py) — плоская упорядоченная цепочка
guard-условий, по одному на состояние: нет мыши → `-`; зарядка → анимация
заливки (таймер главного потока); полный заряд → зелёный значок, уведомление и
новая отметка времени; сон → `Zzz`; мышь на связи, но уровень нечитаем → `?`;
иначе процент — цифрами или заполненной батарейкой.
[`ui/icons.py`](battery_tray/ui/icons.py) рисует цифры средствами PIL, а батарейку
растрирует из SVG-шаблона через `wx.svg` (NanoSVG, входит в состав wxPython);
оба пути сохраняют полноценный альфа-канал вплоть до готового значка.

### Хранение

[`storage.py`](battery_tray/storage.py) держит настройки, закреплённую мышь и
отметку времени последней полной зарядки для каждой мыши в
`HKCU\SOFTWARE\Battery_Tray\`. Из этой отметки и вычисляется строка тултипа с
прошедшим временем.

Всю конструкцию скрепляет одно архитектурное правило: `ui/app.py` никогда не
импортирует модуль драйвера — только `detect_all_drivers()` и контракт
`MouseDriver`.

### Структура

```
battery_tray/
  autostart.py          автозапуск с Windows (значение HKCU Run)
  battery.py            BatteryStatus — универсальная модель статуса
  config.py             настройки (интервал опроса, цвета, шрифт)
  resources.py          пути к ресурсам, совместимые с PyInstaller
  storage.py            дата зарядки, настройки, закреплённая мышь (реестр)
  drivers/
    driver.py           MouseModel, MouseDriver, @register + реестр
    bus.py              один кэшированный снимок hid.enumerate на проход
    hid.py              HidDriver — общая база на одну транзакцию (hidapi)
    hidpp.py            HidppDriver — многошаговая база HID++ (Logitech)
    __init__.py         авто-импорт драйверов -> реестр заполняется
    chipset/            протоколы общего силикона (имя по чипсету)
      nordic52.py       Compx/Nordic 52840 (HID write/read, отчёт 8, 17 байт)
      nordic54.py       Compx/Nordic 54L15 (HID write/read, отчёт 8, 64 байта)
      realtek.py        MCHOSE / RealTek  (push-отчёт 0x13, XOR 0xFF)
    vendor/             протоколы одного бренда
      ninjutso.py       Ninjutso Sora     (HID feature-отчёт 5)
      razer.py          Razer             (HID feature-отчёт 0, OpenRazer)
      lamzu.py          Lamzu             (HID feature-отчёт, iface 2)
      logitech.py       Logitech          (HID++ 2.0 через приёмник)
      attackshark.py    Attack Shark      (входящий HID-отчёт 3, push)
      bloody.py         A4Tech Bloody     (HID feature-отчёт 0 + входящий отчёт 6)
      sony.py           DualShock 4 / DualSense (поток входящих отчётов)
    system/             то, что Windows уже знает сама
      bluetooth.py      любое Bluetooth-устройство (PnP-свойство заряда, CfgMgr32)
  ui/
    icons.py            отрисовка значка трея (цифры PIL + SVG-батарейка)
    tray.py             обёртка над TaskBarIcon
    settings.py         диалог настроек
    about.py            диалог «о программе» (таблица из реестра)
    app.py              wx-приложение + единый автомат состояний
  icons/                встроенные .ico-ресурсы
```
